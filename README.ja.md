# What is Worth?

[English](README.md) · [Deutsch](README.de.md) · [Español](README.es.md) · [中文](README.zh.md) · **日本語** · [Русский](README.ru.md)

What is Worth? は、AI コーディングエージェントがどれだけの API 換算額を消費しているかを表示します。中心となるのは暦月ではなく、週次リセットから次の週次リセットまでのサブスクリプション期間です。さらにアカウントごとに、週の利用枠 1 ポイントが何ドルに相当するかを測定します。

費用は常にトークンから計算します。各 API 応答のトークン数を API の定価で評価したものです。Claude Code が報告する使用率（%）は、その価値をサブスクリプションと比較するためだけに使います。

現在は Claude Code に対応しています。ほかのエージェントはアダプターとして追加できます。すべてローカルで動作し、アカウントもプロキシも不要で、データを送信しません。唯一のネットワーク通信は、1 日 1 回 LiteLLM の価格表をダウンロードすることです。

## 機能

- **週次リセット以降の概要**（ログイン中のアカウント）：使用率、API 換算額、1 ポイントあたりの価値、ペース、上限に達する時期。
- **内訳**：日別、モデル別、プロジェクト別。プロジェクトは git リポジトリで、worktree とサブディレクトリはメインのリポジトリに含めます。プロジェクト別は期間内の全アカウントを対象とします。
- **全アカウントの一覧表**：それぞれ自分の週次期間とリセット時刻で表示します。
- **プラン料金と API 換算額の比較**：各プランの週あたりの定価と、1 ポイントあたりの API 換算額をプランの 1 ポイントあたりの料金で割った倍率。
- **全アカウントの合計**：今日、今週、今月、全期間。
- **過去の週**：そのアカウントのリセット周期に沿って表示します。
- **Claude Code のステータスライン**：週の使用率、リセット以降の費用、1 ポイントあたりの価値、カウントダウン、セッションと直前の依頼の費用。
- **レポート**：全履歴を日別・週別・月別に集計。
- **6 言語**：ドイツ語、英語、スペイン語、中国語、日本語、ロシア語。

ステータスラインの例：

```
週 51% · リセット以降 $8.04 · リセット 月 01:00（残り 3日 7時間） · セッション $24.12 · 今回の依頼 $2.34
```

## 必要なもの

- Python 3.11 以降。ほかのパッケージは不要です。
- Git（プロジェクトの判定とリリースに使用）。
- Claude Code（トランスクリプトは `~/.claude/projects/` に保存されます）。

## インストール

1. リポジトリをクローンします。例：`~/what-is-worth`。
2. リリースを作成します。最新のコミットを `~/.local/share/what-is-worth/app` に書き出します：

   ```
   scripts/release.sh
   ```

3. `wiw` をパスに置きます：

   ```
   ln -s ~/.local/share/what-is-worth/app/bin/wiw ~/.local/bin/wiw
   ```

4. `~/.claude/settings.json` にステータスラインを追加します：

   ```json
   "statusLine": {
     "type": "command",
     "command": "/home/<ユーザー>/.local/share/what-is-worth/app/bin/wiw statusline",
     "padding": 0
   }
   ```

5. 一度すべてを読み込みます。約 2,700 件のトランスクリプトで 10〜20 秒かかります：

   ```
   wiw sync
   ```

Claude Code は既定で 30 日後にトランスクリプトを削除します。履歴を残すには、`~/.claude/settings.json` の `cleanupPeriodDays` を大きな値にしてください。台帳に読み込み済みのデータは、後でトランスクリプトが削除されても残ります。

## 使い方

| コマンド | 内容 |
|---|---|
| `wiw` | 前回の週次リセット以降の概要（`wiw overview` と同じ） |
| `wiw overview --weeks 10` | 過去 10 週を含む概要 |
| `wiw report day` | 日別の費用。`week` と `month` も可。`--since 2026-09-01` も指定可能 |
| `wiw report project` | 全履歴のプロジェクト別費用。`--since` も指定可能 |
| `wiw sync` | 新しいデータを読み込む（通常は自動） |
| `wiw sync --rebuild` | 既存のトランスクリプトを読み直す（読み込み規則の変更後など） |
| `wiw reprice` | 現在の価格表ですべての費用を再計算する |

Claude Code の中では `! wiw` で概要を開けます。モデルを使わないため、トークンは消費しません。

ステータスラインは更新のたびに自分のセッションの新しい行だけを読み込みます。さらに最大 5 分ごとに、全トランスクリプトの読み込みをバックグラウンドで開始します。

## 設定

| 変数 | 意味 | 既定値 |
|---|---|---|
| `WIW_LANG` | 言語：`de`、`en`、`es`、`zh`、`ja`、`ru` | システムの言語、なければ英語 |
| `WIW_DATA_DIR` | 台帳とリリースの保存先 | `~/.local/share/what-is-worth` |
| `WIW_CONFIG_DIR` | 独自価格の保存先 | `~/.config/what-is-worth` |
| `WIW_CACHE_DIR` | 価格表のキャッシュ | `~/.cache/what-is-worth` |
| `WIW_CLAUDE_DIRS` | 追加の Claude 設定ディレクトリ（`:` 区切り） | `~/.claude` と `CLAUDE_CONFIG_DIR` |

独自の価格（たとえば LiteLLM がまだ知らないモデル）は `~/.config/what-is-worth/prices.json` に書きます。キーは LiteLLM と同じで、価格はトークンあたりです：

```json
{
  "claude-new-model": {
    "input_cost_per_token": 0.000004,
    "output_cost_per_token": 0.00002,
    "cache_read_input_token_cost": 0.0000002,
    "cache_creation_input_token_cost": 0.000005,
    "cache_creation_input_token_cost_above_1hr": 0.000008
  }
}
```

その後 `wiw reprice` を実行します。

git で解決できなくなったフォルダー（削除済みの worktree など）は、`~/.config/what-is-worth/projects.json` でプロジェクトに割り当てられます。キーはフォルダーの glob パターンで、サブディレクトリも対象になります：

```json
{
  "~/code/my-app-*": "my-app"
}
```

規則は全履歴にすぐ反映されます。規則が使われるのは、git がフォルダーを対応付けられない場合だけです。必要になるのは主にインストール前の履歴です。インストール後は、worktree が存在するうちに What is Worth? が対応を記録します。

## 計算方法

**データソース。** Claude Code は API の応答ごとにトークン数をセッション単位のトランスクリプトに書き込み、サブエージェントとワークフローは別ファイルに書きます。同じ応答が複数回現れることがよくあります。What is Worth? はメッセージ ID ごとに最後までストリーミングされたコピーを残し、サブエージェントでの再出力よりメインの会話を優先します。

**価格。** 料金は LiteLLM から取得します。入力、出力、キャッシュ読み取り、5 分と 1 時間の 2 種類のキャッシュ書き込みを含みます。加えて、高速モードの 2 倍料金、データ所在地指定の 10 % 加算、1,000 回あたり 10 ドルのウェブ検索、長文コンテキストの料金段階を反映します。プロンプトがしきい値を超えると（例：Haiku 5.5 で 100,000 トークン超）、超過分だけでなくリクエスト全体が高い料金になります。

**サブスクリプション期間とアカウント。** 使用率、リセット時刻、ログイン中のアカウントを知ることができるのはステータスラインだけで、更新のたびに記録します。各応答は、その時点でログインしていたアカウントに属します。`/login` は実行中のすべてのセッションに同時に適用されます。

**1 ポイントあたりの価値。** 期間内で最初に使用率を記録して以降のアカウントの費用を、その後の使用率の増加で割った値です。Claude Code は整数のパーセントしか報告しないため、5 ポイント増えてから表示し、丸め誤差を約 20 % 以下に抑えます。

**1 回の依頼の費用。** セッション内で、ある入力から次の入力までのすべての応答（サブエージェントを含む）。

## 精度

- **ccusage との比較：** 2026 年 8 月〜10 月は、月別・モデル別のトークンと費用が一致しました。その後 What is Worth? は ccusage に残る 2 つの集計ミスを修正しており、影響は費用の約 0.01 % です。
- **料金：** 使用中のすべてのモデルを Anthropic の公式料金ページと照合しました。表は `scripts/official_prices.json` にあります。
- **独立した検証：** `scripts/verify_projects.py` はプログラム本体を使わずに全トランスクリプトを再計算し、プロジェクトごとに台帳と比較します。ccusage の出力を加えることもできます：

  ```
  npx ccusage@latest claude session --json --offline > /tmp/cc.json
  python3 scripts/verify_projects.py /tmp/cc.json
  ```

- **Claude Code 自身のカウンターとの比較：** セッションごとの合計は約 1 % 低くなります。Claude Code が一部のバックグラウンド呼び出しをトランスクリプトに書かないためです。

プラン料金は claude.com/pricing の税抜の定価です：Pro 月 20 ドル、Max 5x 100 ドル、Max 20x 200 ドル。料金ページには Max が「100 ドルから」としか書かれていないため、Max 20x はこれまで知られている価格です。実際の料金は通貨、税、年払い、割引により異なる場合があります。

金額はすべて定価での API 換算額です。Pro や Max のサブスクリプションでは参考値であり、請求額ではありません。

## 既知の制限

- **アカウントはインストール以降のみ。** トランスクリプトにはアカウントが含まれません。最初のステータスライン更新より前の費用は「帰属不明」と表示されます。
- **ステータスラインなしでのアカウント切り替え。** ログイン後に `claude -p` や IDE だけを使うと、切り替えはターミナルのステータスラインが次に更新されたときに検出されます。
- **拒否された最初の試行。** あるモデルが出力前に拒否し別のモデルが回答した場合、フォールバック分は正しく計算されます。拒否された試行に費用がかかるかはカテゴリによりますが、トランスクリプトにカテゴリがないため計上しません。
- **削除済みの worktree。** 最初の読み込み前に削除された worktree はリポジトリに対応付けられず、フォルダー名で表示されます。ただし `projects.json` の規則で割り当てることができます。既知のリポジトリの削除済みサブディレクトリは、引き続きそのリポジトリに含まれます。
- **1 台のマシン。** マシンごとに台帳を持ちます。

## 構成

```
src/whatisworth/
  model.py                 全ソース共通のレコード：応答、依頼、上限、アカウント
  sources/base.py          ソースのインターフェース
  sources/claude_code.py   Claude Code アダプター
  ledger.py                SQLite 台帳
  ingest.py                ロック付きの差分読み込み
  pricing.py               LiteLLM の価格と独自価格
  projects.py              作業ディレクトリ → git リポジトリ
  insights.py              期間、アカウント、合計、1 ポイントあたりの価値
  statusline.py            ステータスライン
  cli.py                   コマンド
  i18n.py, format.py, locales/   言語と書式
```

台帳はトークンと元の事実を保存します。費用は読み込み時に計算され、`wiw reprice` で再計算できます。プロジェクトとアカウントは集計時にだけ割り当てます。Gemini のような新しいソースは、同じレコードを返すアダプターを 1 つ追加するだけです。

## 開発

```
python3 -m pytest -q tests
bin/wiw            # 作業コピーを実行
scripts/release.sh # 最新のコミットをリリース
```

ステータスラインと `wiw` はリリースからのみ実行されるため、作業コピーの未完成の変更が本番で動くことはありません。本番に反映するコミットのたびに `scripts/release.sh` を実行してください。

新しいテキストは `src/whatisworth/locales/` のすべてのファイルに追加します。テストで全言語のキーとプレースホルダーが一致するか確認します。

## 予定

- Gemini CLI を 2 つ目のソースとして、チャットファイルではなく OTel テレメトリーログから読み込む。ルーターと要約の呼び出しも記録されているのはログだけです。
- 同じ集計に基づくブラウザーダッシュボード。
- 自動で対応付けできないフォルダー向けのプロジェクト規則。
