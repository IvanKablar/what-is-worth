# What is Worth?

[English](README.md) · [Deutsch](README.de.md) · [Español](README.es.md) · [中文](README.zh.md) · [日本語](README.ja.md) · **Русский**

What is Worth? показывает, сколько стоимости API расходуют ваши ИИ-агенты для программирования. В центре не календарный месяц, а период подписки — от одного недельного сброса до следующего. Для каждого аккаунта инструмент также измеряет, сколько долларов стоит один процентный пункт недельной квоты.

Расходы всегда считаются по токенам: число токенов каждого ответа API, оценённое по прейскуранту API. Процент расхода, который сообщает Claude Code, служит только для сравнения этой стоимости с подпиской.

Сейчас поддерживается Claude Code. Другие агенты добавляются как адаптеры. Всё работает локально: без аккаунта, без прокси и без отправки данных. Единственный сетевой запрос раз в сутки загружает прайс-лист LiteLLM.

## Возможности

- **Обзор с недельного сброса** для текущего аккаунта: расход, стоимость API, цена процентного пункта, темп и момент, когда будет достигнут лимит.
- **Разбивка** по дням, моделям и проектам. Проект — это git-репозиторий. Worktree и подкаталоги относятся к основному репозиторию.
- **Все аккаунты в одной таблице**, каждый в своём недельном периоде со своим временем сброса.
- **Цена тарифа против стоимости API:** прейскурантная цена каждого тарифа за неделю и коэффициент — стоимость API за процентный пункт, делённая на цену процентного пункта в тарифе.
- **Итоги по всем аккаунтам:** сегодня, эта неделя, этот месяц и за всё время.
- **Прошлые недели** по графику сбросов аккаунта.
- **Строка состояния Claude Code** с недельным расходом, затратами с момента сброса, ценой процентного пункта, обратным отсчётом и стоимостью сессии и последнего запроса.
- **Отчёты** по дням, неделям и месяцам за всю историю.
- **Шесть языков:** немецкий, английский, испанский, китайский, японский и русский.

Пример строки состояния:

```
Неделя 51 % · 8,04 $ со сброса · Сброс Пн 01:00 (ещё 3 д 7 ч) · Сессия 24,12 $ · Запрос 2,34 $
```

## Требования

- Python 3.11 или новее. Других пакетов не нужно.
- Git — для определения проектов и выпуска версий.
- Claude Code, который хранит транскрипты в `~/.claude/projects/`.

## Установка

1. Клонируйте репозиторий, например в `~/what-is-worth`.
2. Создайте выпуск. Он экспортирует последний коммит в `~/.local/share/what-is-worth/app`:

   ```
   scripts/release.sh
   ```

3. Добавьте `wiw` в путь:

   ```
   ln -s ~/.local/share/what-is-worth/app/bin/wiw ~/.local/bin/wiw
   ```

4. Пропишите строку состояния в `~/.claude/settings.json`:

   ```json
   "statusLine": {
     "type": "command",
     "command": "/home/<пользователь>/.local/share/what-is-worth/app/bin/wiw statusline",
     "padding": 0
   }
   ```

5. Один раз считайте всё. Около 2 700 транскриптов обрабатываются за 10–20 секунд:

   ```
   wiw sync
   ```

По умолчанию Claude Code удаляет транскрипты через 30 дней. Чтобы сохранить историю, задайте большое значение `cleanupPeriodDays` в `~/.claude/settings.json`. Уже считанные данные остаются в журнале, даже если транскрипт позже удалён.

## Использование

| Команда | Действие |
|---|---|
| `wiw` | обзор с последнего недельного сброса, то же, что `wiw overview` |
| `wiw overview --weeks 10` | обзор с десятью прошлыми неделями |
| `wiw report day` | расходы по дням, также `week` и `month`, при желании с `--since 2026-09-01` |
| `wiw sync` | считать новые данные; обычно происходит автоматически |
| `wiw sync --rebuild` | перечитать имеющиеся транскрипты, например после изменения правил чтения |
| `wiw reprice` | пересчитать все расходы по текущему прайс-листу |

В Claude Code обзор открывается командой `! wiw`. Модель при этом не используется, поэтому токены не тратятся.

При каждом обновлении строка состояния читает только новые строки своей сессии. Не чаще раза в пять минут она дополнительно запускает в фоне чтение всех транскриптов.

## Настройка

| Переменная | Значение | По умолчанию |
|---|---|---|
| `WIW_LANG` | язык: `de`, `en`, `es`, `zh`, `ja` или `ru` | язык системы, иначе английский |
| `WIW_DATA_DIR` | расположение журнала и выпуска | `~/.local/share/what-is-worth` |
| `WIW_CONFIG_DIR` | расположение собственных цен | `~/.config/what-is-worth` |
| `WIW_CACHE_DIR` | кеш прайс-листа | `~/.cache/what-is-worth` |
| `WIW_CLAUDE_DIRS` | дополнительные каталоги конфигурации Claude через `:` | `~/.claude` и `CLAUDE_CONFIG_DIR` |

Собственные цены, например для модели, которой ещё нет в LiteLLM, задаются в `~/.config/what-is-worth/prices.json`. Ключи — как в LiteLLM, цены — за один токен:

```json
{
  "claude-new-model": {
    "input_cost_per_token": 0.000004,
    "output_cost_per_token": 0.00002,
    "cache_read_input_token_cost": 0.0000002,
    "cache_creation_input_token_cost": 0.000005,
    "cache_creation_input_token_cost_above_1hr": 0.000008
  }
}
```

Затем выполните `wiw reprice`.

## Как считаются расходы

**Источник данных.** Claude Code записывает каждый ответ API с числом токенов в транскрипт сессии, а субагенты и рабочие процессы — в собственные файлы. Один ответ часто встречается несколько раз. What is Worth? оставляет для каждого id сообщения полностью переданную копию и предпочитает основной диалог повторам в субагентах.

**Цены.** Тарифы берутся из LiteLLM. Учитываются ввод, вывод, чтение кеша и обе длительности кеша — пять минут и один час. Дополнительно учитываются двойная цена быстрого режима, надбавка 10 % за размещение данных, веб-поиск по 10 $ за 1 000 запросов и тарифы длинного контекста. Если промпт превышает порог, например 100 000 токенов у Haiku 5.5, по повышенной ставке оплачивается весь запрос, а не только превышение.

**Периоды подписки и аккаунты.** Расход, время сброса и текущий аккаунт известны только строке состояния. Она записывает их при каждом обновлении. Каждый ответ относится к аккаунту, под которым был выполнен вход в момент ответа. `/login` действует сразу для всех запущенных сессий.

**Цена процентного пункта.** Расходы аккаунта с первого показания расхода в периоде, делённые на прирост расхода с того момента. Claude Code сообщает только целые проценты, поэтому значение появляется после прироста на 5 пунктов — так ошибка округления остаётся ниже примерно 20 %.

**Стоимость запроса.** Все ответы сессии от одного ввода до следующего, включая субагентов.

## Точность

- **Сравнение с ccusage:** за август–октябрь 2026 года токены и расходы совпали по месяцам и моделям. С тех пор What is Worth? исправляет две ошибки подсчёта, которые остались в ccusage; они затрагивают около 0,01 % расходов.
- **Тарифы:** все используемые модели сверены с официальной страницей цен Anthropic. Таблица находится в `scripts/official_prices.json`.
- **Независимая проверка:** `scripts/verify_projects.py` пересчитывает все транскрипты без кода программы и сравнивает итоги по проектам с журналом. При желании добавляется экспорт ccusage:

  ```
  npx ccusage@latest claude session --json --offline > /tmp/cc.json
  python3 scripts/verify_projects.py /tmp/cc.json
  ```

- **Сравнение со счётчиком Claude Code:** сумма по сессии примерно на 1 % ниже, потому что Claude Code не записывает часть фоновых вызовов в транскрипт.

Цены тарифов — прейскурантные цены без налога с claude.com/pricing: Pro 20 $, Max 5x 100 $, Max 20x 200 $ в месяц. На странице цен для Max указано только «от 100 $», поэтому цена Max 20x — ранее известная. Фактические цены могут отличаться из-за валюты, налогов, годовой оплаты и скидок.

Все суммы — эквивалент стоимости API по прейскуранту. На подписке Pro или Max это ориентировочные значения, а не счёт.

## Известные ограничения

- **Аккаунты только с момента установки.** Транскрипты не содержат аккаунт. Расходы до первого обновления строки состояния отображаются как «неотнесённые».
- **Смена аккаунта без строки состояния.** Если после входа вы используете только `claude -p` или IDE, смена будет замечена при следующем обновлении строки состояния в терминале.
- **Отклонённые первые попытки.** Если модель отказывает до вывода, а отвечает другая, резервный ответ оценивается верно. Стоит ли что-то отклонённая попытка, зависит от её категории, которой нет в транскрипте, поэтому она не учитывается.
- **Удалённые worktree.** Worktree, удалённые до первого чтения, нельзя сопоставить с репозиторием, и они отображаются под именем папки.
- **Один компьютер.** Каждый компьютер ведёт свой журнал.

## Структура

```
src/whatisworth/
  model.py                 общие записи всех источников: ответ, запрос, лимит, аккаунт
  sources/base.py          интерфейс источников
  sources/claude_code.py   адаптер Claude Code
  ledger.py                журнал SQLite
  ingest.py                пошаговое чтение с блокировкой
  pricing.py               цены LiteLLM и собственные цены
  projects.py              рабочий каталог → git-репозиторий
  insights.py              периоды, аккаунты, итоги, цена процентного пункта
  statusline.py            строка состояния
  cli.py                   команды
  i18n.py, format.py, locales/   языки и форматы
```

Журнал хранит токены и исходные факты. Расходы вычисляются при чтении и пересчитываются командой `wiw reprice`. Проекты и аккаунты назначаются только при анализе. Новый источник, например Gemini, — это ещё один адаптер, выдающий те же записи.

## Разработка

```
python3 -m pytest -q tests
bin/wiw            # запустить рабочую копию
scripts/release.sh # выпустить последний коммит
```

Строка состояния и `wiw` работают только из выпуска, поэтому незавершённые изменения рабочей копии никогда не выполняются вживую. Запускайте `scripts/release.sh` после каждого коммита, который должен попасть в работу.

Новые тексты добавляются во все файлы `src/whatisworth/locales/`. Тест проверяет, что во всех языках одинаковые ключи и заполнители.

## Планы

- Gemini CLI как второй источник, читаемый из журнала телеметрии OTel, а не из файлов чатов. Только журнал содержит ещё и вызовы маршрутизатора и суммаризатора.
- Веб-панель на основе того же анализа.
- Правила проектов для папок, которые нельзя сопоставить автоматически.
